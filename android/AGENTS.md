# Android layer rules

- Both native Focus Shield entry points use FocusShieldReminderView and dedicated Android color resources so the overlay and fallback screen remain visually consistent without changing website styles or blocking logic.
- Verified lock-screen notifications use a persisted native foreground-service projection of the existing session timestamps; notification expiry never awards coins or finalizes a session, because verification and the server ledger remain authoritative.
- Standard countdown uses a separate timestamp-projection foreground service and the existing notification builder, because WebView animation callbacks suspend in background and Verified behavior must remain untouched.
- Countdown sync, clear and finish dispatch on the same UI queue; reboot projection retains wall-clock recovery-break boundaries, because asynchronous cleanup and rebasing must not resurrect or extend a session.
- Personal countdown expiry uses a persisted session-keyed deadline alert separate from silent result updates; accountability completion suppresses already-handled deadlines, because reopening must not generate a late or duplicate alert or settle rewards natively.
- Focus Shield package scans and icon encoding run on a cached single-thread worker preloaded at launch/resume, because synchronous bridge queries block setup painting.
- StudyGoalWidget uses account-scoped native presentation mirrors of existing focus sessions/goals/todos; checkbox desired states remain queued until owner-scoped cloud writes succeed, because launcher actions must survive offline use and midnight without creating rewards or crossing accounts.
- CI publishes the APK/AAB to a rolling `latest-build` GitHub Release (artifacts are optional, 1-day retention), because Actions artifact storage quota blocked downloads.
- Release signing requires the existing upload key and environment credentials; CI can restore an encrypted-secret backup, but cache misses never generate replacement keys and release never falls back to debug signing.
- App Usage Limits run in their own native store/service/overlay (AppLimitsStore, AppLimitsService, AppLimitsOverlay), separate from Focus Shield, because daily limits must not interfere with session blocking; reels limits are converted to minutes web-side (~30s each), usage resets at local midnight, and 50%/100% alerts fire once per day per app.
- App Limits usage comes from the same since-midnight event timeline as Screen Time (ScreenTimeDetails.usage), never aggregated daily buckets, because those buckets are not aligned to local midnight and carried yesterday's minutes into today.
- App Limits detects foreground changes on a dedicated worker using cached exhausted packages and a shared throttled daily usage snapshot; UI only applies the cover, and returning to CommitX clears it on confirmed foreground change rather than a grace timer, because repeated aggregation and timed exemptions delayed blocking.
- The silent ongoing screen-time notification is refreshed by the ScreenTimeReceiver alarm, boot and app resume, because usage data must stay local and current without a foreground service.
- Accountability/Roast delivery is the native AccountabilityEngine (AlarmManager, one alarm slot, one notification id) fed by events from src/lib/accountability.ts, because closed-app delivery and legacy clients must follow the same policy.
- WebView camera/mic grants (Study Buddy cam) are allowed only for CommitX origins after Android runtime permission, because media capture must never extend to arbitrary pages.
- In the Android app, Verified sessions never fail on app switching/multi-window; enforcement is Focus Shield blocking (wall-clock expiry, restored on boot) plus locked back navigation, while the website keeps its strict leave-fails rules.
